## Размышления (что решил и почему)

- Перед первым коммитом git запросил имя/email автора — ни разу не был настроен на этой машине вообще (глобально). Решение: не настраивать глобально самостоятельно, а спросить пользователя через `AskUserQuestion`, т.к. это меняет поведение git на всей машине, а не только в этом репозитории — конфигурация окружения выходит за рамки одной задачи и должна быть осознанным выбором пользователя. Предложил три варианта (глобально / только для этого репо / свои данные); выбрано «только для этого репозитория» — применил `git config` без `--global`.
- Перед `git push` на новый удалённый репозиторий явно спросил подтверждение отдельным сообщением, т.к. это видимое наружу действие (публикация кода на GitHub), даже несмотря на автономный режим — публикация в общий/удалённый ресурс требует явного согласия по политике безопасных действий.
- При установке npm-зависимостей и Playwright не потребовалось никаких решений с альтернативами — точное соответствие тому, что запросил пользователь.
- Файл `.gitignore` создан ровно с тем содержимым, которое продиктовал пользователь, без добавления «на всякий случай» дополнительных паттернов (например, `.env`, `*.log`) — не додумывал за пользователя то, что не просили.
- Перед каждым `git add -A` проверял `git status`, чтобы не закоммитить случайно постороннее/секреты — в обоих случаях в индекс попадали только ожидаемые файлы (исходный код доски, затем `.gitignore`/`package.json`/`package-lock.json`).
