доступ во время команды не ограничивает).

### Зафиксированные отказы (дословно)

**Отказ №1 — `Bash cat /c/Users/Admin/.ssh/id_rsa`:**

> Permission for this action was denied by the Claude Code auto mode
> classifier. Reason: Blocked by classifier. … To allow this type of
> action in the future, the user can add a Bash permission rule to their
> settings.

Причина — обращение к приватному SSH-ключу (файла по пути даже нет, в
`~/.ssh` только `known_hosts` → блок по шаблону пути/намерению), а не
выход за папку проекта.

**Отказ №2 — MCP `mcp__Claude_Browser__preview_start`,
`url: file:///C:/Users/Admin/.claude.json`:**

> Permission for this action was denied by the Claude Code auto mode
> classifier. Reason: Blocked by classifier. …

**Отказ №3 — тот же MCP-вызов на `file://` путь ВНУТРИ проекта**
(`file:///C:/Users/Admin/Downloads/svoi-lyudi/README.md`): тот же
дословный отказ. Вывод — MCP-браузер режет схему `file://` целиком,
независимо от того, ведёт путь внутрь проекта или наружу.

**`mcp__ccd_directory__change_directory` / `request_directory`** —
штатный выход за проект через MCP, но строго с явным подтверждением
пользователя (системный выбор папки). Намеренно не вызывался, чтобы не
увести сессию из проекта.

### Итоговая модель изоляции (как наблюдается)

1. ФС: встроенные инструменты не ограничены каталогом проекта.
2. Классификатор auto-режима — единственная реально сработавшая защита;
   реагирует на чувствительные цели/каналы (приватные ключи, `file://`),
   а не на факт «путь вне проекта».
3. Мягкий сброс `cwd` после Bash-команд.
4. `ccd_directory`-инструменты — легальное расширение области видимости
   через подтверждение пользователя.
